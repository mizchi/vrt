# 課題: 決済のタイムアウトと再試行（日本語の分散システム図）

決済ゲートウェイの呼び出しがタイムアウトし、再試行して成功するまでを
`kind: distributed` のアニメーションとして `scene.json` に書いてください。
読者は日本語話者のバックエンド開発者で、「なぜ二重課金が起きないのか」を
図で説明されたい人です。

ノード（**ラベルは日本語**、id は英字で自由）: 注文サービス、決済ゲートウェイ、
カード会社。

出来事の順序:
1. 注文サービスが決済ゲートウェイへ「課金要求（冪等キー: A1）」を送る。
2. 決済ゲートウェイがカード会社へ「オーソリ」を送り、カード会社が「承認」を返す。
3. ゲートウェイから注文サービスへの「課金完了」の応答が**失われる**（`lost`）。
4. 注文サービスがタイムアウトし、同じ冪等キーで「課金要求（冪等キー: A1）」を
   再送する。
5. 決済ゲートウェイは同じキーを見て課金を繰り返さず、「課金完了（既存）」を返す。

要件: 各メッセージに日本語ラベル。再送のタイミングは絶対時刻ではなく
`after` で前のメッセージに対して書く。冪等キーが同じであることを、注釈
（`value` か `callout` か `relate`）で図の中に示す。キャプションは日本語で。

提出物: `scene.json`、`payment.gif`（`vlmkit-anim video`）、`log.md`。

成功条件: `vlmkit-anim check scene.json` が ✗ も ⚠ もなく 0 で終わる。
`vlmkit-anim layout scene.json` が問題なしと報告する。`explain` が上の順序
として読める。

`log.md` に必ず書くこと: 手で書いた座標・色・キャンバスサイズがあれば全部と
その理由。日本語ラベルで困ったこと（メッセージラベルの幅、ノード名の箱、
ガイドに書いてなかったこと）。図に入れたかったが表現できなかったこと。
